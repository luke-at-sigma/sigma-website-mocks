How project tracking works today

“Leadership sees projects as on-track when they're at risk”

How project tracking works today
  • —Open one tab for tickets, another for the status roll-up
  • —Re-key updates into a deck before every Monday review
  • —Watch green status hide a project that's already slipping
How it works in Sigma
  • ✓Update status and dates in the row you're reading
  • ✓Approve or reassign, then push the change to the source system
  • ✓See the roll-up live, with every change stamped and traceable

3 steps to a live tracker

1
Point at your tables

Sigma queries the project tables in your warehouse live, so the queue reflects today's work.

2
Add editable columns

Input Tables add owner, date, and status fields people type into. Each edit lands in the warehouse.

3
Wire up approvals

Actions route each item to its approver and call the source system's API, so nobody re-keys the update.

3 jobs a tracker has to do

One queue, live from the warehouse

Every open item sits in one table that queries the warehouse directly, so the queue reflects the work as it stands. A slipping program shows up while there is still time to fix it.

  • ✓Sort the queue by age, owner, or SLA breach risk
  • ✓Give each team a filtered view of the same tables
  • ✓Drill from a status count to the rows behind it

Questions ops teams ask

Can Sigma replace our standalone project tracker?+
Yes, for teams whose tracking depends on warehouse data. Sigma holds the queue, the status fields, and the approvals in one workbook. Actions push the same change into a source system through its API. Teams keep specialist trackers where deep task features matter.
Where do status updates get stored?+
Status updates land in your warehouse. Input Tables write to a designated write schema as append-only row-level inserts tagged with change type, primary key, and user identity. Sigma never modifies your production tables. Audit history on Input Tables records every change, so you can trace a value back to the person who entered it.
Do we have to build the app from scratch?+
No, Sigma ships a project management App Template you can start from. It includes sample data, a ReadMe page, and a video walkthrough. A guided source swap points it at your own warehouse tables. Most teams change the columns to match their process.
Which warehouses support Input Table writeback?+
Input Table writeback runs on Databricks and Snowflake, and others like BigQuery and Amazon Redshift. The list keeps growing, so check the Help Center for your connection. Sigma runs live queries against the warehouse you already use, so the tracker inherits the roles and row-level security defined there.
