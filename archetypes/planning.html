How planning works in Sigma
  • ✓Open a plan with the recommendations already filled in

3 steps from targets to approval

1
Seed every row

Input Tables pre-fill every row from live warehouse data. Planners override instead of retyping.

2
Submit at the same time

Hundreds of contributors edit their own rows at once. Row-level security holds each to their scope.

3
Approve and lock

Actions route each submission to its approver. Approved rows lock, and audit history logs the change.

Built for planning at scale

Questions about planning in Sigma

Can hundreds of people plan at the same time?+
Yes. Each contributor edits their own rows in the same workbook, and Sigma writes every entry back as a separate tagged insert, so two planners never overwrite one number. Row-level security holds each person to their own scope. In recent customer calls, one team plans with 120 district managers inside a single interface.
Where do the planned numbers live?+
The numbers live in your own warehouse. Input Tables write each entry into a designated write schema as an append-only row-level insert, and Sigma never modifies your production tables. Each insert carries the change type, the user, and the timestamp. Writeback runs on Databricks and Snowflake, and others like BigQuery and Amazon Redshift.
Do we still need a separate planning tool?+
You can run the whole cycle in one workbook. The inputs, the reporting that follows, and the approval step share the same governed data. Nobody re-keys a roll-up between systems. Headcount planning, demand planning, and territory management ship as App Templates with sample data and a guided swap to your own warehouse tables.
How do approvals lock the plan?+
Actions route each submission to its approver and set the status in place. Approved rows lock, so a later edit lands as a new tagged version instead of overwriting a signed-off number. Audit history shows who submitted, who approved, and when. Sigma Agents can watch the submitted-versus-approved pipeline and flag districts that stall.
