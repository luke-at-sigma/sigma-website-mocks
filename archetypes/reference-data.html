Reference data questions

Can business users edit reference data without a ticket?+
Yes, if their warehouse role grants it. An Input Table is a warehouse object, so the same permissions and row-level security that govern the source decide who can edit which rows. Owners edit values in a spreadsheet interface, and Actions can route each change to an approver first.
Where do the edits get written?+
Edits go into a designated write schema in your own warehouse. Input Tables append non-destructive row-level inserts, so Sigma never modifies production tables and leaves no shadow data set to reconcile. Every insert carries the change type, the user identity, and a timestamp.
Does this replace dbt or add a semantic layer?+
Sigma does neither. It queries your dbt models and warehouse views directly, so dbt stays the modeling source of truth and there is no second semantic layer to keep in sync. Reference data you maintain in an Input Table lands in the warehouse as a table your models read like any other.
Can AI suggest matches for a new mapping?+
Yes, and the suggestion runs on the AI provider you configure. Sigma ships no model of its own, so AI Column and Sigma Agents call your own LLM provider or a warehouse-native model. AI Column runs on Databricks and Snowflake. Score proposed matches in a child table rather than directly on the Input Table.

Give the queue back to owners

Once owners maintain their own definitions, the data team stops maintaining lookups and gets back to shipping models.
